# Audit — 2026-09-23

Scope: full repository review for a plain Raw PHP, Persian RTL, Apache/MySQL shared-hosting deployment.

## Repository structure reviewed

- Front controller: `index.php`
- Route table: `router.php`
- Apache rules: `.htaccess`, `admin/.htaccess`, `uploads/.htaccess`
- Configuration: `config/config.php`, `config/database.php`, `config/local.example.php`
- Helpers/services: `app/Helpers/*`, `app/Services/*`, `app/Middleware/AuthGuards.php`
- Repositories: `app/Repositories/*`
- Public/admin views: `pages/*`, `pages/admin/*`, `views/layouts/*`, `views/partials/*`
- Assets: `assets/css/main.css`, `assets/js/main.js`
- Database: `database/schema.sql`, `database/migrations/*`, `database/seed.sql`
- Tests/docs/uploads rules: `tests/*`, `docs/*`, `uploads/.htaccess`

## Confirmed strengths from current code

- Pure PHP front controller; no framework, Node.js, Docker, Redis or external service dependency.
- PDO helper layer uses prepared statements and disables emulated prepares.
- Public content queries filter `status = 'published'` and `published_at <= now()` in repositories.
- Session setup enables strict mode, HTTP-only cookies, SameSite=Lax and regenerates ID after login.
- CSRF tokens exist for login/logout/admin mutations.
- Login rate limiting is database-backed in `login_attempts` and requires no external cache.
- Upload directory has an `.htaccess` that disables PHP/script execution and directory indexing.
- URL helper and request normalizer already support installations under subdirectories.
- Public routes for `/`, news, articles, reports, events, books, lessons, research, media, topics, search, login, admin and sitemap/robots are present.

## Issues found from actual files

### Installer / deployment

- No `install.php` exists, so a first-time InfinityFree user cannot create `config/local.php`, install schema, run migrations or create the first admin through the browser.
- No install lock exists; reinstall protection is absent.
- `schema_migrations` table is absent, so migration execution cannot be recorded.
- `uploads/media/` is used by upload code but has no tracked placeholder/unignore rule.

### Database alignment

- `events` and `reports` extension tables exist, but the generic admin content create/update route does not create/update those extension rows.
- `users` table exists, but the admin UI has no usable user management routes/views.
- `media` accepts image/audio/video/document, but the media admin route lists only images.
- Migration execution is documented but not integrated into runtime installation.

### Routing / subdirectory

- Public route coverage is mostly present. Admin route coverage is partial: `/admin/content` exists, but type-specific admin pages are only listing shortcuts and users are disabled in the menu.
- Search and 404 responses do not consistently emit `noindex` metadata.

### UI/UX and logo

- No uploaded logo file is present in the repository or workspace. The current header uses a text mark only.
- The CSS contains a duplicated `.hero h1 {` block, which can break following rules in some parsers.
- Mobile hamburger toggles the menu, but there is no overlay, scroll lock, close-on-link-click, or explicit outside close handling.
- Admin dashboard text still says some sections are not active even though routes exist.

### Admin

- Admin authorization is currently admin-only for all admin work. The requested role separation (`user`, `editor`, `admin`) is not fully reflected.
- Generic content form lacks cover media, file/media attachment selection and related-content controls.
- Generic content registry lacks publish/archive/delete actions.
- Topic admin is create/list only; update/delete/archive-style management is absent.
- User admin is absent.

### Security

- SQL is mostly parameterized; remaining risks are authorization/IDOR around admin routes because all are admin-only but editor role is not implemented.
- Upload route checks MIME with `finfo`, size and random names, but does not validate original extension explicitly and stores all files in one `uploads/media` path not tracked in the repo.
- Delete/archive flows for generic content are missing; adding them must include CSRF and server-side authorization.
- Installer must never display or commit database credentials.

### SEO/performance/accessibility

- Base title/meta/canonical/Open Graph/Twitter tags exist.
- JSON-LD support exists in the layout, but public route handlers do not populate Organization/Article/NewsArticle/Book/Event/LearningResource/ScholarlyArticle structured data.
- Sitemap and robots routes exist; robots disallows admin/login/search.
- Search should be noindexed by meta as well.
- Public markup is mostly semantic with skip link and focus styles, but logo/favicons and responsive image/OG logo assets are missing.

### Local test environment limitation

- This sandbox currently has no `php` binary (`php: command not found`), so PHP syntax/runtime tests cannot be executed here. Static inspection, shell checks and file-level validation are still possible; final runtime verification should be done on PHP 8.3+ or the target InfinityFree environment.
