# مدیریت هویت سایت و نصب روی InfinityFree

## تغییر لوگو بدون ویرایش PHP

1. از `/login` با حساب **admin** وارد شوید.
2. در منوی مدیریت، **تنظیمات سایت** (`/admin/settings`) را باز کنید.
3. نام سایت و توضیح کوتاه را تنظیم کنید. برای لوگو، favicon و Open Graph فایل جدا انتخاب کنید.
4. پیش‌نمایش محلی فایل انتخابی را ببینید و **ذخیره تنظیمات** را بزنید. پیش‌نمایش به معنی ذخیره‌شدن نیست.
5. پس از پیام موفقیت، سایت را باز کنید. Header، Footer، عنوان و داده‌های ساخت‌یافته از تنظیمات استفاده می‌کنند. تصویر اختصاصی هر مطلب برای OG آن مطلب بر تصویر عمومی سایت اولویت دارد.
6. برای حذف، گزینه «حذف تصویر اختصاصی و بازگردانی پیش‌فرض» همان تصویر را انتخاب و ذخیره کنید. انتخاب هم‌زمان فایل و بازگردانی برای یک تصویر رد می‌شود.

فایل‌ها: PNG، JPG/JPEG و WEBP؛ هر فایل حداکثر **۲ MiB**، هر ضلع حداکثر **۴۰۹۶** و مجموع حداکثر **۱۲ میلیون پیکسل**. برای favicon تصویر مربع و برای OG اندازه ۱۲۰۰×۶۳۰ توصیه می‌شود. آپلود SVG/ICO/GIF/HTML/PHP مجاز نیست. SVGهای ثابت و مورد اعتماد مخزن فقط fallback هستند.

بدون JavaScript نیز ذخیره، حذف و پیش‌نمایش تصویر فعلی کار می‌کند؛ پیش‌نمایش پیش از آپلود نیاز به JavaScript دارد. تغییر favicon ممکن است تا تازه‌سازی مرورگر در تب قدیمی دیده نشود؛ هر آپلود مسیر تصادفی جدید دارد.

**رمز دیتابیس فقط در فرم Installer وارد می‌شود.** آن را در Git، گزارش، تصویر صفحه یا پیام خطا قرار ندهید. رمز فقط در فایل محلی `config/local.php` ذخیره می‌شود؛ این فایل git-ignored و از دسترسی HTTP مسدود است. رمز مدیر به‌صورت hash در دیتابیس ذخیره می‌شود.

نیازمندی‌ها: PHP 8.3+، PDO MySQL، mbstring، fileinfo، session و JSON. `config/` و `uploads/site/` باید قابل نوشتن باشند. مجوز 777 توصیه نمی‌شود. فایل `uploads/site/.htaccess` را هنگام انتقال فایل‌های مخفی جا نیندازید.

Installer اتصال، Schema، Migration، اعتبارسنجی ساختار، config محلی، ایجاد مدیر و قفل را به ترتیب انجام می‌دهد. پس از موفقیت، `config/installed.lock` مانع نصب مجدد است. فایل‌های migration با checksum ثبت می‌شوند؛ تغییر فایل migration اجراشده به‌جای ساخت migration جدید مجاز نیست.

## ارتقای سایت نصب‌شده

1. از دیتابیس، `config/local.php` و uploads در کنترل‌پنل هاست پشتیبان بگیرید؛ پشتیبان را عمومی یا داخل Git نگذارید.
2. فایل‌های نسخه جدید را **بدون بازنویسی config محلی، قفل نصب یا uploads کاربران** منتقل کنید.
3. با حساب admin به `/admin/settings` بروید. اگر جدول تنظیمات هنوز موجود نیست، دکمه **اجرای ارتقای دیتابیس** ظاهر می‌شود.
4. این دکمه `POST /admin/settings/upgrade` را با همان CSRF و RBAC موجود اجرا می‌کند و از **همان runner نصب** استفاده می‌کند؛ هیچ DDL مخفی در خواندن صفحات اجرا نمی‌شود.
5. قفل نصب و حساب مدیر فعلی حفظ می‌شوند. برای ارتقا **قفل Installer را حذف نکنید**.

اجرای migration به shell، Composer، cron یا ابزار خارجی نیاز ندارد. DDL در MySQL تراکنشی نیست؛ پشتیبان لازم است. شکست migration باید بررسی شود، نه اینکه مکرراً بدون بررسی اجرا شود. عدم دسترسی به جدول تنظیمات می‌تواند ناشی از قطعی DB نیز باشد؛ دکمه ارتقا جایگزین رفع اتصال نیست.

## عیب‌یابی امن

- مرحله شکست به‌صورت مشخص نمایش داده می‌شود: اتصال MySQL / Schema / Migration / اعتبارسنجی / config محلی / ایجاد مدیر / قفل.
- فقط SQLSTATE پنج‌حرفی و کد عددی MySQL ممکن است نمایش داده شوند. متن خام driver، SQL، username، password، session یا secret چاپ نمی‌شود.
- نمونه کدهای عمومی: 1045 دسترسی، 1049 نام دیتابیس، 1142 مجوز جدول، 2002 اتصال. این راهنما جایگزین تست واقعی هاست نیست.
- اگر POST بیش از `post_max_size` باشد، PHP ممکن است کل فرم و CSRF را حذف کند؛ پیام 403 حجم درخواست/نشست را توضیح می‌دهد. `upload_max_filesize` و `post_max_size` باید برای فایل‌های انتخابی کافی باشند (سه تصویر جمعاً تا ۶ MiB به‌علاوه سربار فرم).
- اگر ساخت قفل پس از ایجاد مدیر شکست خورد، نصب مجدد همان مدیر عمداً متوقف می‌شود؛ مجوز config و وضعیت نصب را با پشتیبان بررسی کنید. هیچ حساب موجودی خودکار بازنویسی نمی‌شود.

## پیش از انتشار — تست دستی لازم

روی یک staging با PHP 8.3+/MySQL و Apache، سپس خود InfinityFree:

- نصب تازه، اجرای migration دوباره، ارتقای نصب قدیمی با قفل موجود، رد checksum ناسازگار.
- ورود admin و انتخاب هر سه تصویر، ذخیره واقعی multipart، مشاهده Header/Footer/favicon/OG و JSON-LD.
- تعویض لوگو و حذف لوگو؛ فایل قدیمی پس از commit پاک شود، rollback هیچ تنظیم نیمه‌ذخیره‌شده‌ای نگذارد.
- فایل PHP/HTML/SVG با پسوند PNG، MIME نادرست، فایل بزرگ و نام traversal رد شوند.
- user/editor/مهمان، CSRF غلط و حساب admin تنزل‌یافته نتوانند تنظیمات را تغییر دهند.
- درخواست مستقیم فایل اجرایی داخل uploads با Apache مسدود شود؛ این آزمون را با فایل بی‌خطر و در staging انجام دهید.
- صفحه Settings و سایر صفحات Admin در عرض‌های **360، 375، 390، 430، 768، 1024 و 1280+**، با نام طولانی و لوگوی عریض/بلند؛ اسکرول افقی فقط داخل جدول لازم مجاز است.
- صفحه‌کلید: ترتیب Tab، focus، Escape و منوی موبایل؛ بدون JS امکان ذخیره محفوظ باشد.
- نصب root و `/php`: asset، canonical، OG absolute، sitemap، ورود و redirect.

**وضعیت این جلسه:** این آزمون‌های اجرایی/مرورگری انجام نشده‌اند؛ PHP و Apache/MySQL آماده در محیط نبود. جزئیات در `AUDIT-2026-09-23.md` ثبت شده است.
